# EventScope — анализатор журналов событий

CLI-приложение на Node.js для потокового анализа журналов событий, фильтрации, подсчёта статистики и формирования JSON/CSV-отчётов. Дополнительно поставляется тёмная веб-панель для визуализации сохранённого JSON-отчёта.

## 1. Бизнес-требования

Служба поддержки должна быстро находить частые ошибки и их источники в журналах нескольких компонентов. Приложение должно:

- принимать путь к журналу и параметры через CLI;
- читать файл построчно, без загрузки всего содержимого в память;
- проверять формат `timestamp | level | source | eventCode | message`;
- требовать timestamp ISO 8601 UTC и уровень `TRACE`, `DEBUG`, `INFO`, `WARN` или `ERROR`;
- продолжать обработку после повреждённых строк и указывать номера строк с ошибками;
- фильтровать по времени, уровню и источнику; начало интервала включительно, конец исключительно;
- считать общее число строк, корректные и ошибочные строки, подходящие фильтрам события;
- формировать сводки по уровням и источникам, Top-N кодов событий уровня `ERROR`;
- выводить сводку в терминал и сохранять отчёт в JSON или CSV;
- предсказуемо обрабатывать пустой и отсутствующий файл;
- выдавать детерминированные агрегаты и сортировку Top-N.

## 2. Реализованный функционал

- Построчное чтение через `node:readline` и `createReadStream`.
- Отдельные модули парсера, фильтра, агрегатора, анализатора, вывода и CLI.
- Сочетание всех фильтров.
- Начало диапазона включительно (`>= --from`), конец исключительно (`< --to`).
- Уровни и источники агрегируются в детерминированном алфавитном порядке.
- Top-N сортируется по убыванию количества; при равенстве — по коду.
- Для ограниченного использования памяти сохраняются первые 100 примеров событий и первые 100 ошибочных строк; все счётчики при этом рассчитываются по всему файлу.
- Веб-панель визуализирует статистику, диаграммы, Top ошибок, качество данных и сохранённые примеры событий. Веб-панель открывает JSON-отчёт, созданный CLI; сам анализ больших файлов выполняет CLI.

## 3. Формат журнала

Одна запись на строку:

```text
2025-01-15T10:20:30Z | ERROR | api | DB_TIMEOUT | Database request timed out
```

Требования:
- ровно пять полей, разделённых `|`;
- пустые поля запрещены;
- `|` внутри значения запрещён;
- timestamp — UTC с суффиксом `Z`;
- разрешённые уровни: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.

Пустая строка считается повреждённой записью. Пустой файл без строк даёт нулевые счётчики. Строки с LF и CRLF поддерживаются.

## 4. Установка в WSL

Требуется Node.js версии 20 или новее.

```bash
node --version
npm --version
npm install
```

Если Node.js ещё не установлен, установите актуальную LTS-версию средствами вашей WSL-среды. После установки проверьте `node --version`.

## 5. CLI: параметры и примеры

Общий синтаксис:

```bash
node src/cli.js --input <путь> [--from <ISO-UTC>] [--to <ISO-UTC>] \
  [--level <LEVEL>] [--source <источник>] [--top <N>] \
  [--format <json|csv>] [--output <путь>]
```

Параметры:
- `--input` — обязательный путь к входному файлу;
- `--from` — нижняя граница времени, включительно;
- `--to` — верхняя граница времени, исключительно;
- `--level` — точный уровень; значение уровня нормализуется в верхний регистр;
- `--source` — точное имя источника;
- `--top` — количество кодов `ERROR`, по умолчанию `10`, допускается `0`;
- `--format` — формат сохраняемого отчёта `json` или `csv`;
- `--output` — путь сохранения отчёта; при наличии `--format` обязателен;
- `--help` — справка.

### Пример 1. Полный анализ и JSON

```bash
node src/cli.js --input logs_events_sample.log \
  --format json --output reports/full-report.json
```

### Пример 2. Ошибки API за временной интервал

```bash
node src/cli.js --input logs_events_sample.log \
  --from 2025-01-01T00:00:00Z --to 2025-02-01T00:00:00Z \
  --level ERROR --source api --top 5 \
  --format json --output reports/api-errors.json
```

### Пример 3. Предупреждения и CSV

```bash
node src/cli.js --input logs_events_sample.log \
  --level WARN --top 10 --format csv --output reports/warnings.csv
```

### Пример 4. Только консоль

```bash
node src/cli.js --input logs_events_sample.log
```

Без `--format` и `--output` результат выводится только в терминал. Для создания отчёта укажите оба параметра. Папки для выходного файла создаются автоматически.

## 6. Веб-панель

Сначала сформируйте JSON-отчёт:

```bash
node src/cli.js --input logs_events_sample.log \
  --format json --output reports/report.json
```

Запустите веб-сервер в отдельном терминале:

```bash
npm run web
```

Откройте `http://127.0.0.1:4173`, затем нажмите «Загрузить JSON-отчёт» и выберите `reports/report.json`. Панель работает локально. Chart.js и шрифты загружаются через CDN, поэтому для диаграмм требуется подключение к интернету; основные данные и таблица остаются доступны без диаграмм.

## 7. Тестирование и покрытие

Одна команда запускает все тесты Node.js и создаёт HTML-отчёт покрытия через c8:

```bash
npm test
```

Путь к HTML-отчёту покрытия: `coverage/index.html`. Тесты проверяют корректные/повреждённые строки, неверную и несуществующую дату, уровень, пустые поля, embedded pipe, отсутствующий и пустой файл, границы дат, сочетание фильтров, Top-N, JSON/CSV, только повреждённые данные и большой файл из 12 000 записей.

Для быстрого запуска только тестов без покрытия:

```bash
npm run test:unit
```

### Скрипт одной командой

```bash
chmod +x scripts/test-and-report.sh
./scripts/test-and-report.sh
```

Скрипт запускает тесты с покрытием и сообщает путь к HTML-отчёту. Числовые проценты покрытия смотрите в выводе `npm test` и в `coverage/index.html`. Целевой порог проекта — не менее 80% строк исполняемого кода. Процент необходимо подтвердить запуском в целевой WSL-среде; если покрытие ниже, добавьте тесты до сдачи.

**Область измерения:** модули бизнес-логики `src/` (парсер, фильтр, агрегатор, анализатор и вывод). Исключения из метрики: `src/cli.js` как тонкая точка входа, `web/**` (сервер и клиентская часть интерфейса), HTML/CSS-ресурсы, конфигурация и тесты. c8 собирает покрытие Node.js; клиентский код браузера не инструментируется c8. Параметры `--include=src --exclude=src/cli.js --exclude=web/**` зафиксированы в команде `npm test`.

## 8. Архитектура

```text
src/
  parser.js      Валидация и разбор строки
  filter.js      Проверка и применение фильтров
  aggregator.js  Потоковые счётчики и ограниченные примеры
  analyzer.js    Построчное чтение файла и координация
  output.js      Терминальный вывод, JSON и CSV
  cli.js         Аргументы командной строки
web/
  server.js      Локальная раздача веб-панели
  public/
    index.html   Разметка панели
    styles.css   Тёмная адаптивная тема
    app.js       Загрузка отчёта и визуализация
test/            Автоматические тесты
scripts/         Вспомогательные скрипты
```

## 9. Ограничения и заметки

- Агрегаты рассчитаны по всему файлу, но в JSON сохраняются только первые 100 примеров событий и первые 100 ошибочных строк, чтобы не расходовать память пропорционально размеру журнала.
- `topErrors` учитывает только записи с уровнем `ERROR`.
- Фильтрация по `source` выполняет точное совпадение.
- При повреждённой записи обработка продолжается; номер строки относится к исходному файлу.
- Сервис веб-панели предназначен для локального использования и не реализует аутентификацию.

## 10. Зависимости

- Node.js 20+ (встроенные `node:readline`, `node:fs`, `node:test`);
- `c8` — покрытие тестами;
- Chart.js CDN — диаграммы в веб-панели.
